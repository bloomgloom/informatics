# 소켓으로 랜덤 채팅 만들기

채팅은 1:1 대화처럼 보이지만 실제로는 기다리는 서버와 찾아가는 클라이언트의 관계라는 것을 네 단계로 경험하는 수업 자료입니다. 대화는 연결 하나로 번갈아 하며, 클라이언트가 먼저 말합니다.

| 단계 | 서버 | 클라이언트 | 교사 실행 |
|---|---|---|---|
| 1 혼자 해 보기 | 학생 | 학생 | 없음 |
| 2 서버 열어 보기 | 학생 | 교사 | `./start-client.sh` |
| 3 클라이언트로 접속 | 교사 | 학생 | `./start-server.sh` |
| 4 랜덤 채팅 | 학생 | 학생 | `./start-random.sh` |

학생 코드는 단계 1의 코드에서 단계 3에 주소만 바뀝니다. 단계 4에서는 학생끼리 직접 연결하지 않고 교사 프로그램이 이어 줍니다.

```
학생A client -> 교사 -> 학생B server
학생B client -> 교사 -> 학생C server
```

| 파일 | 내용 |
|---|---|
| `server.py` | 교사 프로그램 (설치할 것 없음) |
| `setup.sh` / `setup.bat` | 설정 (Mac / Windows) |
| `start-client.sh` / `.bat` | 단계 2: 교사가 클라이언트 |
| `start-server.sh` / `.bat` | 단계 3: 교사가 서버 |
| `start-random.sh` / `.bat` | 단계 4: 랜덤 채팅 |
| `random-chat-activity-server.ipynb`, `random-chat-activity-client.ipynb` | 학생용. 코드 없이 빈 칸만 있고, 교사 설명을 들으며 따라 칩니다. 두 파일을 함께 나눠 줍니다. 코드는 `%%writefile`로 저장해 별도의 터미널 창 두 개에서 실행합니다. |
| `logs/` | 학생 대화 기록 (git 제외) |

## 수업 전 확인

**단계 2와 4에서 교사 컴퓨터가 학생 컴퓨터의 서버로 접속해야 합니다.** 그래서 학생 컴퓨터마다 들어오는 연결(기본 6000번)이 열려 있어야 합니다.

- 학교 망이 기기끼리 통신을 막으면 동작하지 않습니다.
- 학생 컴퓨터에서 방화벽 허용 창이 뜨면 허용해야 합니다. 관리자 권한이 필요할 수 있습니다.
- **수업 전에 학생 컴퓨터 한 대로 끝까지 시험합니다.** 단계 4에서 접속에 실패하면 말을 보냈을 때 클라이언트 창에 이유가 나옵니다.

## 설정: setup

```bash
./setup.sh
```

`config.example.json`으로 `config.json`을 만듭니다. 묻는 것은 없습니다. 값을 바꾸려면 이 파일을 직접 고칩니다. git에서 제외됩니다.

- `student_ip_start`, `student_ip_end`: 학생 컴퓨터 IP의 끝자리입니다. 기본값은 101~130이고, 교사 컴퓨터와 같은 대역에서 찾습니다.
- `blocked_words`: 학생 이름을 차단하려면 여기에 넣습니다.

**API 키는 저장하지 않습니다.** `start-client`, `start-server`, `start-random`을 켤 때마다 묻습니다. Enter를 치면 LLM 없이 고정 답장과 규칙 검사만 씁니다.

## 단계 2: 교사가 클라이언트

```bash
./start-client.sh
```

설정한 범위의 학생 서버(6000번)에 `scan_interval`(기본 3초)마다 접속을 시도합니다. 학생마다 서버를 켜는 시점이 달라도 연결되고, 접속 중인 학생에게는 다시 걸지 않습니다. 연결되면 `안녕하세요?`로 시작하고 LLM이 답합니다. 학생이 서버를 다시 켜면 다시 접속합니다.

같은 주소로 반복 접속하므로 **학교 보안 장비가 막거나 경고할 수 있습니다.** 범위를 교실 컴퓨터로 좁히고, 수업 시간에만 켭니다.

## 단계 3: 교사가 서버

```bash
./start-server.sh
```

화면의 교사 IP와 포트를 알려 줍니다. 학생 클라이언트가 먼저 말하면 LLM이 답합니다. 연결마다 `reply_limit`(기본 5회)까지 답하고, 그 뒤에는 `/끝`을 입력하도록 안내합니다.

## 단계 4: 랜덤 채팅

앞 프로그램을 `Ctrl+C`로 끄고 실행합니다.

```bash
./start-random.sh
```

학생은 서버를 먼저 켜고 클라이언트로 접속합니다. 인원을 확인하고 **Enter**를 누르면 한 학생의 클라이언트를 다른 학생의 서버로 잇습니다. 인원이 홀수여도 모두 이어지고, 한 학생은 클라이언트 창과 서버 창에서 서로 다른 친구와 대화할 수 있습니다. 그 뒤에는 대기자를 자동으로 잇습니다. 신고로 끝난 두 학생은 다시 잇지 않습니다.

## 서버 창 명령

| 명령 | 뜻 |
|---|---|
| Enter | 매칭 시작 (랜덤 채팅에서만) |
| `list` | 접속자 번호, IP, 연결 상태 |
| `kick 번호` | 내보내고 이번 수업 동안 그 IP의 접속을 막음 |
| `Ctrl+C` | 서버 끄기 |

학생은 메시지 대신 `/신고`, `/끝`을 입력할 수 있습니다. `/끝`은 학생 클라이언트 코드에서 처리합니다.

## 안전 장치

- 모든 검사는 교사 서버에서 합니다. 학생이 자기 코드를 고쳐도 피할 수 없습니다.
- **규칙 검사:** 전화번호와 긴 숫자, 링크, 욕설 단어, `blocked_words`
- **LLM 검사:** 규칙을 통과한 메시지를 Claude가 검사합니다. 실패하면 규칙 검사만 적용하고 서버 창에 경고합니다. 메시지 전달이 조금 늦어지고 API 요금이 나갑니다. 내용이 Anthropic으로 전달되므로 학생에게 미리 안내합니다.
- 차단이 3번 쌓이면 60초 동안 보낼 수 없습니다. 차단과 신고는 서버 창에 바로 표시됩니다.
- 상대의 IP는 학생에게 보이지 않습니다.
- 학생 서버 코드는 단순하게 하려고 접속한 상대를 가리지 않습니다. 옆자리 친구와 합의한 경우가 아니면 직접 연결하지 않도록 지도합니다.

필터는 초성이나 변형 표현으로 피할 수 있습니다. 교사가 교실에 있는 수업 시간에만 켜 둡니다.

## 기록

`logs/모드-날짜-시각.jsonl`에 시간, IP, 대화 내용, 차단 여부, 매칭, 신고가 남습니다. 차단된 원문도 포함됩니다.

- 기록된다는 사실은 활동지에 적혀 있고, 단계 4에서 대기 중에 보내는 안내에도 나옵니다. 시작 전에 말로도 안내합니다.
- IP와 시간으로 학생을 특정할 수 있는 민감한 기록입니다. 저장소 밖으로 옮기지 말고, 보관 기간을 정해 삭제합니다.
- 기록과 익명 채팅 수업이 학교 규정에 맞는지 미리 확인합니다.
